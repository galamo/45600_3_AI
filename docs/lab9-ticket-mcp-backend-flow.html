Two paths, same db.json

UI path Browser loads static ui/ from the backend, then calls GET /api/meta, GET/POST /api/tickets, users, projects, sprints — same origin on :4000.
MCP path Host signs in via POST /auth, opens Streamable HTTP on :3300/mcp with a Bearer JWT, then tools/call — MCP proxies REST to the backend.
Shared store MCP owns no data. backend-client.js hits /api/*; store.js reads/writes backend/data/db.json.

The same hop, at a glance

UI is not MCPThe board is vanilla JS served by the backend. Filters, create/edit, status changes — all plain /api fetches.

MCP is a façadeTools like create_ticket resolve names to ids, then call the same REST the UI uses. Role gates: viewer reads; admin writes.

JWT opens the doorNew MCP sessions require a verified Bearer token from POST /auth. Role on the JWT decides which tools are registered.
