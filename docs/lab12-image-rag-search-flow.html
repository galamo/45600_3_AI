Lab 12 — from upload to reranked search

react · express · vision · pgvector

An image leaves the React UI, hits POST /api/images/upload, gets described by a vision indexing agent, embedded, and stored in PostgreSQL + PGVector. Later a keyword query embeds, retrieves candidates, and a reranker agent scores them before cards return to the client.

Two phases, one stack

Index POST /api/images/upload → save file → vision agent → embed indexedText → insert image_documents + vector.
Search GET /api/images/search?q=… → embed query → PGVector top-20 → reranker agent → ranked cards to React.

The same hop, at a glance

Vision writes the searchable textThe indexing agent returns title, tags, objects, and a rich indexedText paragraph — that string is what gets embedded, not raw pixels.

Retrieve, then rerankQuery embedding pulls ~20 nearest rows by cosine distance. The reranker scores relevance with reasons — not similarity alone.

Keys stay on the serverOpenRouter vision, embeddings, and reranker models run only in Express. React talks to /api via the Vite proxy.
